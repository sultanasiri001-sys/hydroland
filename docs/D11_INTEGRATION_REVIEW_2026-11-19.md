# D11 combined localization and accessibility candidate

This candidate composes the declared 105-file interface inventory with the
accepted C11 custom-form and C04 customer-case implementations and the A06
monitor change. It includes a real language control for the visitor and six
authenticated portals, sign-in and the active native dialog. Arabic remains the
initial language; choosing English changes authored interface text and direction
without changing the account, request, permission or business source.

The declared inventory contains 104 interface/binding sources and one unchanged
license-field parser. The parser is deliberately not translated: its canonical
keys and extraction semantics remain source data. Stored names, message bodies,
provider errors, document clauses, saved field labels, signature evidence and
PDF source content remain opaque. API option values, routes, JSON/FormData
payloads and financial amounts retain their canonical representation.

## Independent review and corrections

Implementation was divided across core/participant, documents/governance and
commerce/support. A separate assistant reviewed each delivered boundary; the
integration reviewer reran the supplied actual-module fixtures on the combined
source. These are technical code reviews, not appointments of staff, specialist
signatures or operational acceptance by a customer.

The review found and corrected concrete defects before publication:

- Ten original document-module strict directives had been displaced by injected
  helpers. They are restored as directive prologues; the original directive
  sequences were compared again.
- Eleven document display parameters were escaped both by their callers and by
  the new output sink. They now enter the escaping sink as raw parameters.
  Actual module cases preserve `A&B <نص>` and literal markup as text without
  creating elements or changing saved column keys.
- Calendar/report builders contained joined identifier and message-provenance
  defects. Populated-data cases were added and passed after correction.
- Local authored Error messages lost their live translation when caught.
  Private identity maps retain only authored descriptors. Server text, even text
  identical to a catalog key, stays opaque. Eight participant cases failed
  before the focused correction and passed afterward. A safety conflict retains
  its draft and disabled submit state while appending the refresh action.
- A queued dialog observer could run after an isolated document was disposed.
  A bounded document/body guard removes that teardown error without changing
  active dialog behavior.

Structural comparisons found no changes to the inspected JSON, FormData,
query-string or form-value contracts. The document and commerce comparisons
covered 76 and 61 JSON constructions respectively; the participant error
follow-up preserved 33 JSON constructions and 944 guard expressions. A changed
staff navigation selector was reviewed in its local container because an Arabic
ARIA label is no longer a stable selector. Explicit canonical route identities
replace translated-text routing where required.

## Local verification on the combined source

- 134 web Node tests and the six existing validators passed.
- The production web build passed with the pinned dependency set.
- 773 browser cases in 107 files were discovered. Discovery is not execution.
- Seven committed participant runtime cases and eight participant-error cases
  passed against the combined actual modules and localization engine.
- The actual full application loaded the twelve inspected public surfaces and
  all authenticated portals without console errors or non-GET requests in the
  synthetic fixture. The remaining Arabic account initials are opaque user
  data, as intended.
- Actual language-control interactions in JSDOM verified one visible control,
  sign-in/dialog takeover and restoration, retained drafts and focus, and both
  directions. These observations do not establish native keyboard events,
  browser layout or screen-reader output.

The local host denies Chromium's required Unix socket. No local Chromium,
viewport, native PNG or Orca pass is claimed.

## Required CI evidence before merge

The complete Web validation suite must execute the declared forms, commerce,
support, participant and real-switch cases. The language suite includes desktop,
tablet and mobile-width geometry, canonical routing, menu keyboard behavior,
operational form drafts, revoked access and retained visual artifacts. Existing
C04 assignment/customer-response tests and C11 immutable form/version tests
remain in their workflows.

The separate native screen-reader job uses headed Chromium, Orca, AT-SPI,
Speech Dispatcher and installed Arabic/English voices. It observes actual Orca
diagnostics and genuine audio from an isolated native sink, with quiet windows,
signal checks and retained per-control WAV evidence. It rejects missing voices,
missing speech, unavailable audio, dirty source and untracked served source.
An independent reviewer checked the native harness, including negative PCM
cases and supported runtime parameters; the actual native CI run is still
required. See [native acceptance scope](D11_NATIVE_SCREEN_READER_ACCEPTANCE.md).

The A02 full-main release inventory now requires both Web validation jobs and
the native runtime/acceptance steps. Its digest is pinned, and all 23 existing
release-inventory tests pass. Retained screenshots, audio and source receipts
remain synthetic and contain no customer data or provider credentials.

## Acceptance boundaries

This change does not execute a payment, publish a campaign, grant a role, issue
a medical or external training clearance, change a stored contract, or create
an operational department acceptance. No API, Prisma model or database migration
is added by the D11 diff against its accepted prerequisites.

The native harness is a bounded Linux screen-reader smoke check. It does not
grade pronunciation, every form's reading order, human usability, physical
mobile devices or other assistive technologies. Those claims require their own
evidence. No D11 tracker closure follows from source translation, test discovery
or this review document alone: actual CI, visual review and deployment evidence
must identify the final accepted source.
