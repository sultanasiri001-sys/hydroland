# المرحلة الثالثة — تسليم رسائل الحساب

هذه الوثيقة تخص مرحلة الحساب والمصادقة في خطة الواجهات الثماني.

## الخلل والإصلاح

كان عامل البريد يقرأ أقدم 25 إشعارًا بحالة PENDING، بما فيها الرسائل المرسلة التي لم يُستخدم رابطها بعد والرسائل المؤجلة لمحاولة لاحقة. امتلاء الدفعة بهذه السجلات يمنع وصول العامل إلى الرسائل الجديدة.

أصبح اختيار الرسائل المستحقة يتم قبل حد الدفعة. تبقى الرسالة المرسلة PENDING حتى استخدام رابطها، وتنتهي صلاحية التحديات المرسلة والمؤجلة دون إعادة إرسالها. انقطاع قاعدة البيانات المؤقت ينتج تحذيرًا آمنًا ومحاولة في الدورة التالية، دون رفض غير معالج من المؤقت.

لا يتغير مخطط قاعدة البيانات أو تصميم الواجهات. يعتمد ترتيب مواعيد JSON على صيغة UTC ISO الموحدة التي يحفظها AuthService وعامل البريد.

## جاهزية البريد في واجهة الحساب

تقرأ الواجهة حالة تشغيل ميزة البريد من /integrations/email/public-config، الذي يعيد enabled فقط دون اسم المزوّد أو تشخيص بيانات الاعتماد. يعتمد هذا الفحص على متطلبات إعداد المرسل والمزوّد نفسها المستخدمة عند الإرسال، ولا يثبت تسليم رسالة فعلية.

يتوقف زر إنشاء الحساب وطلب رسائل التفعيل والاستعادة حتى نجاح التحقق من جاهزية البريد. توضح الواجهة حالات الانتظار وعدم التوفر وفشل الاتصال، وتسمح بإعادة التحقق. يبقى تسجيل الدخول والمصادقة الثنائية والاستكشاف واستخدام روابط التفعيل والاستعادة الصادرة سابقًا متاحًا. تحتفظ عمليات الخادم بطابور التحديات القائم.

تظل التفاصيل التشغيلية في /health/integrations/email محمية بصلاحية الإدارة. لا تُخزّن استجابة الجاهزية العامة في الذاكرة المخبأة، ولا تحتوي على أسرار أو تفاصيل حسابات المستخدمين.

## التحقق

تتضمن API validation تجربة فعلية على PostgreSQL ومزوّد HTTP محلي يحاكي Resend:

- 25 رسالة مرسلة و25 مؤجلة تسبق الرسائل الجديدة، مع التحقق من عدم تعطيل الإرسال.
- حقول JSON المفقودة وnull، والمحاولات المستحقة، وانتهاء الصلاحية.
- دفعات بحد 25 رسالة، ومنع إعادة إرسال الرسائل الناجحة.
- إعادة المحاولة بعد فشل المزوّد بنفس الرابط ومفتاح منع التكرار.
- تعطيل الإرسال عندما يكون المزوّد CONFIGURED فقط، والتعافي من فشل قراءة قاعدة البيانات.
- استخدام روابط التفعيل والاستعادة المرسلة في AuthService الحقيقي، ومنع إعادة استخدامها وإلغاء الجلسات بعد تغيير كلمة المرور.

التجربة ترفض قواعد البيانات غير المحلية، وتستخدم عناوين example.invalid ومزوّدًا على 127.0.0.1 فقط. لا ترسل رسائل خارجية.

التشغيل بعد تجهيز قاعدة اختبار محلية ومخطط Prisma وبناء API:

    node apps/api/scripts/auth-email-outbox-db-e2e.mjs

## متطلبات التشغيل الخارجي

| الربط | المطلوب في خدمة API على Render |
|---|---|
| رسائل التفعيل والاستعادة | RESEND_API_KEY صالح، وHYDROLAND_EMAIL_FROM من نطاق إرسال موثّق، وHYDROLAND_EMAIL_PROVIDER=RESEND |
| روابط الرسائل | HYDROLAND_PUBLIC_WEB_ORIGIN يطابق أصل واجهة الإنتاج |
| تشغيل البريد | تفعيل HYDROLAND_INTEGRATION_EMAIL_STATUS بعد التحقق من المزوّد؛ حالة SANDBOX تستخدم المزوّد الفعلي أيضًا |
| Google | GOOGLE_CLIENT_ID لعميل ويب، وأصل الواجهة مسجّل ضمن Authorized JavaScript origins لدى Google |

تُدخل القيم السرية في إعدادات الخدمة، ولا توضع في المحادثات أو المستودع. وجود الكود أو نجاح تجربة المزوّد المحلي لا يثبت تسليم بريد إنتاجي أو جاهزية Google. يشترط إغلاق هذين البندين التحقق من إعدادات المالك واختبارهما فعليًا بتفويض مناسب.

مراجع إعداد المزوّد: [Google Identity Services](https://developers.google.com/identity/gsi/web/guides/get-google-api-clientid)، و[توثيق نطاق الإرسال في Resend](https://resend.com/docs/dashboard/domains/introduction).
