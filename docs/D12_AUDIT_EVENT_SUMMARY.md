# مراجعة أحداث الجهة

يقرأ التصنيف `D12.v2` نسخة مأذونًا بها من سجل `AuditEvent` ويعرض عدد الأحداث والسجلات المرتبطة بها داخل جهة وفترة محددتين. تعمل الأداة محليًا على البيانات المقدّمة إليها. تستخدم اللوحة التنفيذية قائمة التصنيف نفسها عند قراءة أحداث الجهة من قاعدة البيانات.

```sh
node scripts/d12-audit-summary.mjs --organization ORG_ID \
  --from 2026-11-17T21:00:00Z --until 2026-11-18T21:00:00Z < audit.ndjson
```

يضم كل سطر كائن JSON واحدًا من السجل. الحقول المستخدمة هي `id` و`action` و`resource` و`resourceId` و`occurredAt` و`metadata.organizationId`. تشمل الفترة وقت البداية وتستبعد وقت النهاية. يعتمد الإسناد على معرّف الجهة المسجل في الحدث.

| المجموعة | ما يدخل في العدد |
| --- | --- |
| البحث | طلب بحث زائر مسجل بإصدار D12.search.v1 ونطاق PLATFORM دون actor أو IP؛ يسنده الخادم إلى جهة المنصة الداخلية فقط. |
| الحجز | طلب حجز باسم الجهة |
| الأهلية | تحديث بيانات مشارك يعيد أهليته إلى المراجعة |
| الرحلة | نشر رحلة من مسار المركز أو المشغّل البحري |
| التكليف | إسناد معاملة إدارية |
| خدمة العملاء | إنشاء قضية للجهة أو الرد عليها |
| الحوادث | تسجيل بلاغ سلامة باسم الجهة |
| الاعتمادات | تسجيل اعتماد إداري من المالك |

يعطي تكرار معرّف الحدث نفسه نتيجة واحدة. تُعدّ الردود المستقلة أحداثًا منفصلة حتى لو تعلقت بالقضية نفسها. يتيح `sourceDigest` مطابقة نتيجتين من المصدر والفترة نفسيهما، ويعرض التقرير إجراء المصدر وموقعه في الكود لكل مجموعة. العدد صفر يصف السجلات المطابقة داخل النسخة المدخلة فقط.

تبقى العروض والدفع والصرف في `unmeasured` في أداة تصنيف AuditEvent وحدها؛ تقرأ اللوحة التنفيذية مصادرها المستقلة المبينة أدناه. يبقى مرجع المبالغ والإيراد والذمم هو السجلات المالية المختصة. ويقتصر مخرج التصنيف على العدادات ومراجع الكود وبصمة المطابقة.

## اللوحة التنفيذية

يفتح مدير المنصة «إعدادات المنصة» في بوابة الإدارة ثم «اللوحة التنفيذية». يختار جهة وفترة بالتوقيت السعودي ويضغط «عرض التقرير». يستعلم الخادم عن صلاحية ADMIN النشطة، وتحقق الحساب وملكية الجهة الداخلية، وتطابق البريد المعتمد في إعداد الخادم `D12_OWNER_EMAIL` مع الحساب في قاعدة البيانات. يعود المسار بالمنع عند غياب الإعداد. لا تتطلب الميزة ترحيلًا لقاعدة البيانات.

| المؤشر | المرجع وحدود القياس |
| --- | --- |
| الأحداث والسجلات المعنية | صفوف AuditEvent ذات الجهة والإجراء ونوع المورد المطابقين. لكل حدث معرّف أساسي واحد. يتبع عدد السجلات المميزة نوع المورد ومعرّفه. |
| العروض | سجلات عروض الدورات التي أنشأتها الجهة في الفترة، بجميع حالاتها. |
| المدفوعات | سجلات Payment المنشأة لحجوزات رحلات الجهة، بجميع حالاتها. |
| الإيراد المرحّل | مجموع FinanceEntry.amountMinor لقيود REVENUE بحالة POSTED بتاريخ الترحيل، لكل عملة. |
| الذمم المفتوحة | مجموع Receivable.outstandingMinor للفروع التابعة للجهة وقت القراءة، للحالات OPEN وPARTIALLY_PAID وOVERDUE، لكل عملة. |
| طلبات البحث العام المسجلة | AuditEvent / PUBLIC_SEARCH_SUBMITTED / PublicSearch بإصدار D12.search.v1 ونطاق PLATFORM، ووقت الخادم occurredAt. تظهر في تقرير جهة المنصة فقط. تقارير المراكز تعرض «غير منطبق — البحث العام على نطاق المنصة». |
| سجلات مطابقة التسويات المسجلة | FinanceSettlementImport.submittedAt للفروع المرتبطة بالجهة عبر OrgUnit.organizationId. لكل id سجل واحد؛ النسخ المختلفة من الاستيراد سجلات مستقلة. |
| التسويات المميزة | عدد أزواج centerOrgUnitId وproviderSettlementId المميزة بين سجلات الاستيراد في الفترة، دون إخراج هذين المعرّفين. |
| سجلات التسويات المقبولة والمرفوضة | الحالات النهائية APPROVED وREJECTED بتاريخ reviewedAt، حتى لو كان الاستيراد قبل الفترة. اكتمال القبول منفصل عن قرار المراجع الفردي. |
| قرارات مراجعة التسويات | FinanceSettlementReview.createdAt، مفصولة إلى APPROVED وREJECTED، ومع عدد importId المميزة. لا يضاعف ربط المراجعات عدد سجلات الاستيراد. |
| التحويل البنكي المؤكد | غير مقاس؛ اعتماد المطابقة المسجلة لا يثبت تنفيذ تحويل بنكي. |

عقد اللوحة `D12.dashboard.v2` وعقد التسويات `D12.settlement-records.v1`. جميع الفترات نصف مفتوحة بتوقيت الرياض. لا تُخرج إحصاءات التسويات السطور أو الملاحظات أو مراجع المزود أو الأطراف أو مبالغ جديدة، ولا تنشئ أو تعدل أي حركة مالية.

## تسجيل طلب البحث العام

يرسل المتصفح `POST /api/v1/discovery/search-events` عند إرسال بحث غير فارغ في وضع الزائر فقط. يحتوي JSON على `eventId` من نوع UUIDv4 و`schemaVersion: "D12.search.v1"` فقط. لا يُرسل نص البحث أو نتيجته أو معرف الحساب أو الجهة أو ملفات الارتباط، ولا يتضمن الرابط بيانات بحث. لا تمنع مشكلة القياس عمل البحث المحلي.

يرفض الخادم أي حقل إضافي أو إصدار آخر أو معاملات URL، ويحل جهة المنصة من إعدادها القائم. عند غياب الجهة أو عدم نشاطها يفشل التسجيل دون كتابة. يسجل الحدث دون actorId أو ipAddress أو requestId؛ وتحتوي metadata فقط على schemaVersion وscope وorganizationId المحسوم من الخادم. إعادة UUID نفسه لا تكتب سجلًا جديدًا أو تغير وقته، وتصادمه مع حدث آخر يرفض دون تعديل ذلك الحدث.

حد الكتابة 60 حدثًا جديدًا لكل دقيقة على مستوى المنصة، محمي بمعاملة Serializable وقفل قاعدة بيانات مشترك بين نسخ الخدمة. يوجد أيضًا حد دخول محلي ثابت قدره 180 طلبًا صحيح البنية لكل دقيقة لكل عملية، دون مفاتيح IP أو زائر. قد يُرفض التسجيل بالحد أو يفشل اتصال المتصفح؛ لذلك تعني الأعداد «طلبات مسجلة» ولا تمثل أشخاصًا فريدين أو ضمان تسجيل كل بحث. العد يبدأ مع نشر المصدر ولا يعيد إنشاء تاريخ البحث السابق.

يستخدم اختبار القبول قاعدة PostgreSQL مؤقتة باسم `hydroland_d12_uat`، وجلسات دخول عادية وبيانات مالية مصطنعة. يشغّل ملف `.github/workflows/api-validation.yml` اختبار API والمتصفح. يتطلب التفعيل ضبط عنوان مدير المنصة على خدمة API والتحقق من إصدار API والويب بعد النشر.
