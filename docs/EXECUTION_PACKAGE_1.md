# HYDROLAND — Execution Package 1

## الهدف
بناء أول مسار تشغيلي كامل وقابل للاختبار داخل المنصة:

إنشاء الحساب → التحقق → الملف الشخصي → طلب دور مهني → إضافة مؤهل → رفع الإثبات → إرسال للمراجعة → مراجعة بشرية → قرار → إشعار → سجل تدقيق.

## المبادئ الملزمة
- التسجيل لا يعني التفعيل.
- الشخص ≠ الحساب ≠ الدور ≠ المؤهل ≠ التفويض.
- الانتقالات بين الحالات يفرضها الخادم، وليس الواجهة.
- لا توجد موافقة ذاتية.
- المستندات تحفظ في تخزين خاص، مع بصمة ملف وسجل تاريخي.
- الصلاحية = الدور × الإذن × النطاق × الحالة × السياق.
- العرض لا يعني التنزيل أو التصدير.
- الذكاء الاصطناعي لا يعتمد المؤهلات ولا يمنح الأدوار ولا يصل مباشرة إلى قاعدة البيانات.
- جميع القرارات الحساسة تسجل في سجل تدقيق غير قابل للمحو التاريخي.

## حالات طلب التفعيل
مسودة → تم الإرسال → تحت المراجعة → معلومات إضافية مطلوبة → أعيد الإرسال → معتمد → مرفوض → معلق → منتهي/مؤرشف عند انطباق الحالة.

## حالات التحقق من المؤهل
غير متحقق → بانتظار التحقق → تم التحقق من الوثيقة → متحقق وفق وسيلة معتمدة → مرفوض → منتهي.

## اختبارات القبول الأساسية
- منع مستخدم من قراءة مستندات مستخدم آخر.
- منع اعتماد الطلب مباشرة من الواجهة دون صلاحية.
- منع المراجع خارج النطاق من اتخاذ القرار.
- منع IDOR عبر معرفات قابلة للتخمين.
- رفض MIME مزيف والملفات غير المسموح بها.
- اختبار الجلسات المنتهية.
- اختبار إعادة الإرسال بعد طلب معلومات إضافية.
- اعتماد الطلب وتفعيل الدور وإرسال الإشعار وإنشاء سجل التدقيق ضمن معاملة منضبطة.
