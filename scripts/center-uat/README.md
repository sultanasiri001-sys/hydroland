# Isolated center acceptance sandbox

Deploy `render.center-uat.yaml` from its dedicated branch, using a new free database and web service. Do not attach production or recovery databases, environment groups, provider credentials, or customer records. Automatic deployment is disabled. Render Free Postgres expires after 30 days; this environment is temporary and has no backups.

The Blueprint starts disabled (`HYDROLAND_UAT_ENABLED=false`) so it cannot seed unknown credentials. After resources are provisioned, use the Render connector to set a newly generated private secret of at least 24 characters as `HYDROLAND_UAT_PASSWORD` and `HYDROLAND_UAT_ENABLED=true`, then deploy the tested commit. Keep Blueprint automatic sync disabled to preserve this explicit activation. JWT is independently generated by Render. Each actor signs in through the ordinary application login with `ACTOR@center-uat.hydroland.test`; the individual password is `passwordFor(ACTOR, secret)` exported by `seed.mjs`. Deliver these passwords privately. Never commit them or copy production credentials.

| Actor | Scope |
| --- | --- |
| manager | Center A manager, independent shift review |
| accountant1 | Center A accountant |
| accountant2 | Center A handover recipient |
| finance1 | Center A central finance approval |
| finance2 | Center A finance manager approval |
| admin | Platform admin only; no center employment |
| outsider | Center B only, for negative isolation checks |

Schema bootstrap accepts an empty dedicated database or an exact matching sandbox marker. It preserves existing sandbox transactions on restart and refuses other databases or changed schema. The pinned SQL in `schema/` is attributed in `sources.json`; it supplements the current canonical Prisma schema. This is a synthetic TEXT-key bootstrap, not production baseline adoption or proof of production migration parity.

The CI acceptance workflow builds the actual API and Web, uses PostgreSQL 18, verifies real persisted login sessions, center/account isolation, expense entry, handover, independent shift review, two-person period approval, duplicate denial and restart preservation. Its historical period is empty: it tests the approval mechanics, not a real financial close. The smoke script refuses non-CI or non-local databases.

Human acceptance remains required. Log in as each actor, verify the corresponding screens, then record actual/expected results and reviewer sign-off. Invoice/payment/receivable and document/upload fixtures are not seeded. External payment, email, SMS, storage and government integrations are unconfigured, so this sandbox cannot establish their acceptance. Do not enter real customer information or real payment details.
