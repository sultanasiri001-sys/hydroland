# Isolated center acceptance sandbox

Deploy `render.center-uat.yaml` from its dedicated branch, using a new free database and web service. Do not attach production or recovery databases, environment groups, provider credentials, or customer records. Automatic deployment is disabled. Render Free Postgres expires after 30 days; this environment is temporary and has no backups.

The Blueprint starts disabled (`HYDROLAND_UAT_ENABLED=false`) so it cannot seed unknown credentials. After resources are provisioned, use the Render connector to set a newly generated private secret of at least 24 characters as `HYDROLAND_UAT_PASSWORD` and `HYDROLAND_UAT_ENABLED=true`, then deploy the tested commit. Keep Blueprint automatic sync disabled to preserve this explicit activation. JWT is independently generated by Render. Each actor signs in through the ordinary application login with `ACTOR@center-uat.hydroland.test`; the individual password is `passwordFor(ACTOR, secret)` exported by `seed.mjs`. Deliver these passwords privately. Never commit them or copy production credentials.

| Actor | Scope |
| --- | --- |
| manager | Center A manager, independent shift review |
| accountant1 | Center A accountant |
| accountant2 | Center A handover recipient |
| finance1 | Center A central finance approval |
| finance2 | Center A finance manager approval |
| admin | Platform admin only; no center employment |
| outsider | Center B only, for negative isolation checks |

Schema bootstrap accepts an empty dedicated database or an exact matching sandbox marker. It preserves existing sandbox transactions on restart and refuses other databases or changed schema. The pinned SQL in `schema/` is attributed in `sources.json`; it supplements the current canonical Prisma schema. This is a synthetic TEXT-key bootstrap, not production baseline adoption or proof of production migration parity.

The CI acceptance workflow builds the actual API and Web, uses PostgreSQL 18, verifies real persisted login sessions, center/account isolation, expense entry, handover, independent shift review, two-person period approval, duplicate denial and restart preservation. Its historical period is empty: it tests the approval mechanics, not a real financial close. The smoke script refuses non-CI or non-local databases.

Human acceptance remains required. Log in as each actor, verify the corresponding screens, then record actual/expected results and reviewer sign-off. Three synthetic invoices and four captured-payment fixture records are added once by `finance-fixtures.mjs`, with two non-login customer records. Existing accounts, credentials and financial work are preserved on restart. No actual payment provider is invoked. See `finance-acceptance-ar.md` for the human acceptance scenario.

`license-fixture.mjs` generates a clearly marked synthetic PDF for center license attachments. `licenses-smoke.mjs` uses the real account sessions to verify upload/download byte equality, invalid file/date denial, private responses, center isolation, deduplication, registration immutability, independent internal review, integrity failure and restart preservation. It runs only through the disposable CI smoke harness; no license records are automatically seeded at startup. Follow `license-acceptance-ar.md` for human testing. Center license bytes are stored in the dedicated database and do not require external object storage. This does not validate the separate diver credential storage integration.

External payment, email, SMS, object storage and government integrations are unconfigured, so this sandbox cannot establish their acceptance. Do not enter real customer information or real payment details.

## Current-release schema upgrade

The 20 October synchronization brings the current application code into this separate UAT branch. The only recognized existing schema is the original, observed marker `87bf3eadfb4e06a697baf76d10c0d647d65ebf79f9516f0faaba05d34e85610b`; the reviewed target is `dac77738890d60a25db17992e9a047a3ea73d4b40833f6abf0ae8a3e3421766c`. Unknown markers or target generations are refused.

`upgrade.mjs` verifies the original checksums and applies the three published marine-document/organization migrations together in the existing bootstrap transaction. It requires the precise standalone legacy UAT booking index, rejects constraint ownership/dependencies or partially applied target objects, and preserves the original TEXT keys. It locks existing application tables and compares every original row—including accounts, sessions, finance activity, audit history and document bytes—before advancing the marker. A failure rolls back schema and marker together. The UAT-only `HydrolandUatUpgrade` table records the executed batch and source checksums; no production Prisma migration history is invented. A fresh current database leaves that upgrade table empty because it did not execute the historical upgrade.

Fresh current initialization includes the two SQL-only active-booking partial unique indexes. Every startup checks the target columns, indexes, foreign keys and optional upgrade evidence. Repeated startup preserves existing seeds and saved activity. Only aggregate preservation counts and an aggregate digest are logged after the upgrade transaction commits. Failed bootstrap emits a fixed failure event with the source-controlled stage and code, exits nonzero, and suppresses raw exception details; user records, passwords, file contents and provider credentials are never logged.

The workflow first rebuilds the old schema from the pinned historical source in a disposable loopback database, verifies rollback/refusal and concurrent startup, preserves populated license/session/finance records, and compares the upgraded full logical catalog with a fresh current database. It then runs the existing real-session smoke suite. These checks are CI-only. Do not execute them against the saved Render UAT database. Deployment of this synchronization remains a separate coordinated action after the exact-head CI checks pass; this source change does not itself assert a live upgrade or human acceptance.
